# Smart-drone / FireScout

Идея проекта — замечать признаки пожара с дрона и отправлять оповещение на телефон. На борту предполагаются ESP32, датчики MQ-2, KY-026, GY-906, GPS и камера ESP32-CAM.

Пока оборудования нет, поэтому первая версия работает с симулятором. Можно посмотреть показания, вызвать тревогу и проверить, что произойдёт при потере связи. Для Android написан BLE-клиент, но на настоящем устройстве он ещё не проверялся.

## Как попробовать

Скачай репозиторий через **Code → Download ZIP**, распакуй и открой [FireScout-demo.html](FireScout-demo.html) в браузере. Устанавливать что-либо для демо не нужно, интернет тоже не нужен.

Нажми **«Начать симуляцию»** и выбери сценарий:

- **Обычный полёт** — спокойные показания, тревоги нет.
- **Признаки пожара** — несколько датчиков срабатывают, появляется предупреждение и запись в журнале.
- **Одиночный сигнал** — только датчик пламени сообщает о срабатывании. Приложение показывает подозрение, но не объявляет тревогу.
- **Потеря связи** — пакеты перестают приходить. Через более чем 5 секунд показания скрываются и появляется сообщение об отсутствии данных.

В демо высота задана как 5 метров, перемещение — рядом со стартом, в пределах 10 метров. Это просто сценарий для проверки интерфейса, а не проверенная дальность Bluetooth. Высота и заряд батареи в симуляции фиксированные.

## Как определяется тревога

Сейчас логика простая: температура от 60 °C, сигнал MQ-2 от 1800 ADC и срабатывание KY-026 считаются признаками пожара. Если хотя бы два признака есть в трёх пакетах подряд, приложение показывает «Возможный пожар».

Пакеты приходят раз в секунду. Чтобы снять тревогу, нужны пять спокойных пакетов подряд. Потеря связи сама по себе тревогу не снимает. Повторные и старые пакеты не засчитываются как новые подтверждения.

Пороги выбраны для демонстрации. На реальном дроне их придётся подбирать по измерениям. Значение MQ-2 здесь — сырой сигнал датчика, не концентрация газа и не процент дыма.

## Что есть в приложении

- Показания температуры, MQ-2, датчика пламени, GPS, высоты и батареи.
- Схема положения дрона относительно старта, без загрузки карты из интернета.
- Журнал последних 100 тревог с временем и координатами. События симуляции помечаются отдельно.
- Поиск совместимого BLE-устройства, подключение и приём телеметрии в Android-версии.
- Системные уведомления на Android, если пользователь их разрешил. В браузере уведомления для локального файла могут быть недоступны; предупреждение на экране и журнал от этого не зависят.

Координаты в журнале относятся к **дрону**, а не к очагу пожара. Если GPS не определил положение, это отмечается в событии.

## Чего пока нет

Камера ESP32-CAM пока только в планах: видео и распознавание огня по изображениям не сделаны. Управления полётом и прошивки для ESP32 тоже нет.

Мониторинг работает только при открытом приложении. При сворачивании Android-приложения BLE отключается, а симуляция останавливается. Для продолжения нужно запустить её или подключиться заново.

Для настоящего устройства нужно написать прошивку под [описанный BLE-протокол](PROTOCOL.md), подключить датчики и проверить их работу. Сейчас передаются только показания, без изображений. Протокол учебный, без собственной аутентификации и шифрования на уровне приложения.

## Сборка Android

Нужны JDK 17, Gradle 8.11.1, Android SDK 35 и Build Tools 35.0.0. Проект использует Android Gradle Plugin 8.9.2 и рассчитан на Android 8.0 и новее. Для первоначальной загрузки инструментов понадобится интернет.

Открой корень репозитория в Android Studio и настрой SDK и Gradle. Gradle Wrapper пока не добавлен. Если Gradle уже установлен и доступен в терминале, сборка запускается из корня проекта:

```sh
gradle :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

При желании можно создать wrapper:

```sh
gradle wrapper --gradle-version 8.11.1
```

После этого на Windows для сборки можно использовать `gradlew.bat :app:assembleDebug`.

Симуляция не требует разрешения на Bluetooth. Для BLE-подключения Android 12+ запросит доступ к устройствам поблизости, а старые версии — разрешение на местоположение для сканирования. На Android 8–11 может понадобиться включить системное местоположение. Уведомления включаются отдельной кнопкой.

## Проверки

Для тестов нужен Node.js. Из корня проекта:

```sh
node --test tests/core.test.cjs tests/ui.test.cjs
```

Проходят 8 тестов: подтверждение тревоги, одиночное срабатывание, повторные пакеты, переполнение счётчика, потеря связи, отказ датчиков, разбор пакетов и переходы состояний интерфейса.

APK пока не собирался. Работа BLE и уведомлений на телефоне, а также внешний вид в браузере ещё не проверены. Тесты интерфейса проверяют его логику, а не реальное отображение на экране.

## Файлы проекта

- `app/src/main/assets/` — интерфейс, симулятор и логика обнаружения.
- `app/src/main/java/dev/firescout/MainActivity.java` — Android-часть: WebView, Bluetooth и уведомления.
- `tests/` — тесты на Node.js.
- `PROTOCOL.md` — формат пакетов для будущей прошивки.
- `FireScout-demo.html` — автономное браузерное демо.
